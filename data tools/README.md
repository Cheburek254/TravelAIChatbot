# TravelAIChatbot API — Сервис инструментов и логистики

Актуальная инструкция запуска находится в [корневом README](../README.md). Docker Compose из этой папки запускает полный проект с PostgreSQL. Каталог читается из SQL, JSON-файлы используются только для заполнения базы. Чат подключён через OpenRouter (`OPENROUTER_API_KEY`, `OPENROUTER_MODEL`).

Высокопроизводительный движок данных, умного семантического поиска и набора инструментов (Tool Calling) для ИИ-помощника по поездкам.

---

## Подбор времени перелётов

Основная модель — `google/gemini-3.5-flash-lite`. Инструмент перелётов поддерживает границы времени вылета туда, обратного вылета и прибытия домой (`departure_after/before`, `return_departure_after/before`, `return_arrival_after/before`). Сервер проверяет конечное деморасписание; неудачная смена рейса сохраняет текущие карточки. Пожелания «вернуться вечером» и «обратный вылет вечером» различаются. Полная [история коммитов](../README.md#история-коммитов) находится в основном README.

## 🧭 Описание компонентов и инструментов

Сервис **Travel Data & Tools Engine** отвечает за фундамент системы:
1. **`search_destinations`** — поиск направлений по «вайбу», погоде, сезону («где тепло в ноябре», «шале в горах»), бюджету и времени перелета.
2. **`search_hotels`** — поиск отелей в каталоге с обогащением жизненными атрибутами:
   - 🐾 **Pet-friendly** (разрешенные животные, вес, доплата, условия).
   - 👶 **Baby crib & дети** (наличие детской кроватки, детский клуб, безопасность).
   - 💳 **Депозит** (отсутствие скрытых залогов или их размер).
   - ⏱️ **Время заезда и выезда** (14:00/12:00, ранний заезд/поздний выезд).
   - 🛡️ **Условия отмены** (бесплатная отмена до даты X, гибкий тариф).
   - 🍽️ **Питание** (RO, BB, HB, AI).
   - ✨ **Векторный поиск по атмосфере** («шале с камином», «первая линия пляжа»).
3. **`search_transfers_and_flights`** — подбор авиабилетов (прямые, с багажом) и трансферов с автоматическим **анализом состыковки времени прилета и заселения в отель (check-in)**.
4. **`get_weather_forecast`** — реальный прогноз через бесплатный **Open-Meteo API** с климатическим фоллбэком и туристическим вердиктом.

Все инструменты возвращают **чистый JSON** и оформлены в виде стандартных **OpenAI Tool Call (JSON Schema)**, полностью готовых для внедрения в граф **LangGraph / State Machine** или агентные оркестраторы.

## 🚀 Быстрый старт

```bash
# 1. Клонирование репозитория
git clone https://github.com/Cheburek254/TravelAIChatbot.git
cd TravelAIChatbot

# 2. Создание переменных окружения в корне проекта
cp .env.defaults .env

# 3. Запуск сервиса в Docker
docker compose up --build -d
```

После старта откройте в браузере:
- **Интерактивный дашборд проверки инструментов**: [http://localhost:8080/tools-dashboard](http://localhost:8080/tools-dashboard)
- **Интерактивная документация Swagger UI**: [http://localhost:8080/docs](http://localhost:8080/docs)
- **Healthcheck**: [http://localhost:8080/health](http://localhost:8080/health)

## 💻 Локальный запуск без Docker (Python)

Для первого запуска из корня репозитория создайте `.venv` и установите Python-пакеты через этот же интерпретатор: полные команды Windows / Linux / macOS находятся в [инструкции установки](../README.md#после-свежего-клонирования-установка-зависимостей). Для команд ниже перейдите в `data tools` и активируйте окружение.

```bash
# Установка зависимостей
python -m pip install -r requirements.txt

# Демонстрационный прогон всех инструментов в терминале
python demo.py

# Запуск тестов
python -m unittest discover -s tests -v

# Запуск API сервера (с живым расписанием Яндекса при наличии ключей)
python main.py

# Запуск API сервера с принудительным использованием мок-данных расписания
python main.py --yandex-rasp false
```

## 🤝 Интеграция с AI Agent Orchestrator

### Вариант A. Прямой импорт в Python (рекомендуется для монорепозитория / LangGraph)

```python
from src.tools.travel_tools import (
    search_destinations,
    search_hotels,
    search_transfers_and_flights,
    get_weather_forecast
)
from src.tools.tool_definitions import OPENAI_TOOL_DEFINITIONS, execute_tool_call

# 1. Передача схем инструментов в LLM (OpenAI / Anthropic / LangChain)
llm_with_tools = model.bind_tools(OPENAI_TOOL_DEFINITIONS)

# 2. Выполнение вызванного моделью инструмента
result = execute_tool_call(
    tool_name="search_hotels",
    arguments={
        "destination": "Шерегеш",
        "vibe_query": "уютное шале с камином",
        "pet_friendly": True
    }
)
```

### Вариант B. Вызов по HTTP REST API (если агент запущен в отдельном сервисе)

- `GET /health` — проверка работоспособности (`{"status": "ok"}`)
- `GET /api/tools/schemas` — получение JSON Schema всех инструментов
- `POST /api/tools/execute` — универсальный запуск:
  ```json
  {
    "name": "search_destinations",
    "arguments": {
      "query": "где тепло в ноябре с ребенком без долгого перелета",
      "limit": 3
    }
  }
  ```
- `POST /api/tools/destinations`
- `POST /api/tools/hotels`
- `POST /api/tools/transfers-flights`
- `POST /api/tools/weather`

## 📦 Зависимости и переменные окружения

- **Python**: 3.12
- **FastAPI / Uvicorn**: асинхронный высокопроизводительный веб-сервер
- **Pydantic v2**: валидация схем и типов
- **HTTPX**: запросы к OpenRouter / Groq и Open-Meteo API
- **Векторный движок**: сходство частот токенов с расширением синонимов и косинусной мерой; внешняя модель эмбеддингов не используется

Переменные окружения (корневой `.env`):
- `APP_PORT=8080` (порт приложения)
- `APP_HOST=0.0.0.0`
- `DATABASE_URL=` (подключение к PostgreSQL или SQLite; подробности в [корневом README](../README.md#своя-база-данных-и-свой-каталог))
- `OPENROUTER_API_KEY=` / `GROQ_API_KEY=` (для ответов модели через OpenRouter / Groq)
- `YANDEX_RASP_ENABLED=true` (`true` — живое расписание Яндекса при наличии ключей, `false` — мок-данные каталога)
- `YANDEX_RASP_API_KEYS=` (ключи API Яндекс Расписаний через запятую)

## 🧪 Сидирование данных и своя БД

Все данные моков и синтетических датасетов хранятся в формате JSON в директории `data/`:
- `data/destinations.json` — база направлений с помесячным климатом, вайбами, перелетами и активностями.
- `data/hotels.json` — демонстрационный каталог отелей с детальными жизненными политиками.
- `data/transfers.json` — маршруты, авиарейсы и трансферы.

Данные сидируются автоматически в SQL (`destinations`, `hotels`, `routes`, `chat_sessions`) при старте приложения без дополнительных команд. Для подключения собственной базы данных задайте `DATABASE_URL` в корневом `.env` (см. [Своя база данных и свой каталог](../README.md#своя-база-данных-и-свой-каталог)).

## Семейная поездка и расписания

Редакторы взрослых, детей с возрастом и города вылета сохраняют состав в сессии и ваучере, пересчитывают смету и соблюдают бюджет. Маршруты с пересадками проверяются по участкам; среди подходящих вариантов предпочтение прямому авиарейсу. Изменение длительности пересчитывает цену, условный перенос тех же ночей её сохраняет. Найденные ошибки передачи полей, обработки вопросов и ротации ключей покрыты регрессионными тестами. Правила демотарифов, настройка Яндекса и [история коммитов](../README.md#история-коммитов) описаны в корневом README.

## Разговорные запросы

Модель поддерживает интерпретацию пожеланий с `request_quote` и `interpretation` в инструменте сборки. Бюджет и наличие проверяет сервер, обсуждение сохраняет план. Общие сокращения раскрываются до разбора, исходные реплики сохраняются. Причины отказа передаются отдельно от сообщений провайдера. Ранний заезд учитывается в цене и таймлайне, ваучер использует московское время. Подробности и история — в [корневом README](../README.md) и [CHANGELOG](../CHANGELOG.md).
